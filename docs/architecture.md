# Architecture and limits

Statify is an OMP extension that filters *tool results*, not the agent's prompts or final replies. It leaves the main model unchanged. For setup and modes, see [Setup](setup.md); for measured outcomes and methodology, see [Benchmarks](benchmarks.md).

## Tool-result flow

1. On each `tool_result`, Statify considers only a successful, single text result from `read` or `grep` and the latest user task. It skips results shorter than 4,000 UTF-16 characters, longer than 21,600, and results needing more than 12 chunks. Errors, images, `bash`, its own tool, `skill://` and plan reads, requests for full output, and text or tasks matching its secret patterns bypass classification. Secret detection is heuristic, **not** a guarantee that sensitive data cannot leave the machine. OMP may already have truncated a result before Statify sees it.
2. It splits eligible text into chunks of at most 1,800 UTF-16 characters, preferring a blank line before a top-level block in the last 400 characters of a chunk, then a nearby line break. It avoids splitting UTF-16 surrogate pairs; this is a conservative text heuristic, not an AST parser, and long blocks can still split. Structural boundaries can make a result under 21,600 characters exceed 12 chunks, in which case it passes through unchanged.
3. With `replace` or `shadow`, Statify posts the latest task (up to 1,500 characters) and each chunk to OpenRouter's Decisions endpoint using `typesafe/jev-1.13`. The classification instructions and criteria are authored in English; user tasks and tool output are not translated. Scores at or below 0.15 authorize omission; uncertain chunks remain. Missing or invalid answers, network failures, and other processing errors leave the original result intact.
4. In `replace`, the original extension-visible text is archived locally **before** the external request. A successful replacement includes selected chunks, the original `read` path/hashline header when present, and a receipt listing exact shown and omitted ranges. Statify keeps the original instead if the receipt is not shorter in both UTF-16 characters and OMP's local `o200k_base` token count. That token count is a local estimate of main-model input, not actual billed usage; the Jev request may already have incurred a charge. An archive not used for a replacement is removed. `shadow` pays for the classification but never replaces output or creates an archive.

## Modes, recovery, and privacy

Statify starts **off**. Enabling it with a key selects `replace` unless the session's `--statify-mode` flag selects `shadow` or `record`. `record` sends nothing to Jev and never changes tool output; `shadow` sends eligible text for a paid comparison while preserving the original. Switching off affects subsequent results, not an already-sent request. Without explicit `on` and a key, Statify does not send prompts or code to OpenRouter. Once enabled, the latest task and eligible tool text **may leave the machine**; the secret-pattern bypass is not comprehensive. Do not enable it on data that cannot be sent to that provider.

A replacement's receipt includes a UUID, SHA-256 hash, and 1-based inclusive **UTF-16 offsets in the archived tool result**, not source-file line numbers. `xd://statify_read` accepts that UUID and an inclusive range such as `1-2000`, returning exact archived text, up to 8,000 UTF-16 characters per call; a range must not split a surrogate pair. The ID resolves only within the current session's archive directory. File-backed sessions store archives beside the session file and can recover them when reopened; ephemeral-session archives are removed on shutdown. Recovery cannot retrieve content OMP removed before the extension ran. For omitted file content, an ordinary `read` of the relevant source-file ranges is another option when the file remains available; it is not a byte-for-byte snapshot guarantee if the file changed.

OMP's `statify usage` log records status and numeric provider-reported Jev input tokens, output tokens, and USD cost when supplied. This is **Jev cost only**: compare it alongside main-model charges, prompt-cache effects, latency, and any rereads. A shorter result does not guarantee lower total cost or correct classification; omissions can hide important context despite the recovery path. See [Benchmarks](benchmarks.md) for the scope and limits of the measured runs.

[Caveman Skill](https://github.com/JuliusBrussee/caveman/blob/main/skills/caveman/SKILL.md) is an optional, separate way to make an agent's *replies* brief; it does not compress `tool_result`, and Statify does not impose that writing style. Statify independently follows the useful principles of exact recovery and leaving already-sent conversation prefixes unchanged. It neither copies BSL-1.1 Caveman Engine/Proxy source nor claims verified Proxy integration with OMP; stacking a second compression layer could obscure recovery and needs separate testing.
